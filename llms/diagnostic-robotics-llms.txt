# Diagnostic Robotics

> Clinical AI company (Tel Aviv / Boston) whose platform turns medical claims, EHR and FHIR data into
> predictive risk stratification, actionable care next steps, HCC/RAF risk-adjustment gap closure and
> automated care operations for health plans, providers and care organizations. Two public API projects are
> documented on a Stoplight-hosted developer portal. Access is never self-serve: credentials are issued per
> customer and production runs on a per-customer subdomain.

Generated by API Evangelist on 2026-08-12. Diagnostic Robotics does not publish an llms.txt of its own
(/llms.txt returns 404 on diagnosticrobotics.com and docs.diagnosticrobotics.com).

## APIs

- [Precision Population Health API](https://docs.diagnosticrobotics.com/docs/proactive-patient-risk-feed-api/usgko1x40nf1c-diagnostic-robotics-api): OpenAPI 3.0.2, 15 operations. Dataset upload, OAuth token, risk lists, risk profiles, patient profiles, HCC/RAF risk-adjustment profiles, embeddable widgets. Base: https://[CLIENT].precision-population-health.diagnosticrobotics.com
- [Patient Questionnaire API](https://docs.diagnosticrobotics.com/docs/patient-questionnaire-api/6530c434c2f93-diagnostic-robotics-api): Swagger 2.0, 13 operations. Patients, visits, adaptive questions, symptoms, medical summary, triage outcomes. Base path /api/pq
- [Symptom Search Service](https://docs.diagnosticrobotics.com/docs/patient-questionnaire-api/suy7vq94ei15e-search-service): Swagger 2.0, 2 operations. Symptom autocomplete and per-visit symptom listing. Base path /api/search

## What an agent should know

- Authentication for the population-health API is OAuth 2.0 client credentials posted as
  `application/x-www-form-urlencoded` to `POST /api/oauth/token`; the result is a bearer token. The
  questionnaire and symptom services instead take an `x-client` API key header. Neither is self-serve.
- The customer identity is the HOST, not a header: `https://[CLIENT].precision-population-health.diagnosticrobotics.com`.
- There is NO idempotency contract, NO documented rate limit, NO 429 response and NO Retry-After header. Writes
  (`PATCH .../diagnoses`, `POST .../NextStep/{id}/$update`, dataset upload) are not documented as retry-safe.
- Errors are the FastAPI `{"detail": ...}` envelope, not RFC 9457 problem+json. 422 carries a
  `HTTPValidationError` with a `loc` path per failing field.
- Pagination on `GET /api/v2/RiskList/{id}` is `offset` and `limit`, documented in the guide but missing from
  the OpenAPI parameters.
- Widget endpoints answer `204` with a `Location` header holding a signed URL whose token expires in minutes -
  embed it, never cache it.
- Every payload in this API is PHI: patient names, dates of birth, state, ICD/HCC diagnoses and risk scores.
- The `OAuth2AuthorizationCodeBearer` scheme in the published spec points at an Auth0 tenant that no longer
  exists; do not attempt that flow.
